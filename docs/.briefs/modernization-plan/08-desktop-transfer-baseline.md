The extracted baseline is under `baseline/Verified Package/jftp-5.0.2-SNAPSHOT`. The distinct caller directory is `baseline/Other Working Directory`. The synthetic home and files are under `desktop-transfer-baseline`. Use `loopback-baseline/ports.json`, `pid.txt` and `service.log` to verify the fixture process and ports. If the old test certificate changed, import the new test PEM into a fresh isolated JKS as in the protocol probe. Never use the global trust store.
3. From the caller directory invoke the extracted `jftp.bat` with process-local `JAVA_TOOL_OPTIONS=-Duser.home=<scratch>/desktop-transfer-baseline/home`. Redirect stdout and stderr to scratch logs. Verify the selected **Not Connected** tab and use **Manage favorite FTP sites** to connect with the synthetic profiles below. Keep the packaged build and test home separate from any personal jFTP data.

## Exercise the real application

1. **Validation, cancellation and refusal.** Press F3 with a disconnected tab. Submit the empty connection form, observe validation and hostname focus, then cancel. Connect using **03 Login refusal** and confirm the application stays disconnected, its log reports authentication failure, and the server records the refused user without a remote listing.
2. **Independent FTP and FTPS tabs.** Connect using **01 FTP** and confirm the remote marker in `/ftp-start`. Open a second tab with Ctrl+N and connect using **02 FTPS**. Confirm the marker in `/ftps-start`. Switch tabs and verify the original directory and listing are still present. The FTPS fixture enforces encrypted control and data channels. In a separate disconnected tab, the **05 Certificate warning** profile intentionally uses a hostname that differs from the test certificate's CN. Decline the warning, confirm that attempt does not become usable and that the valid FTPS tab still works. Report if the warning cannot be reproduced.
3. **Binary round trip.** On the FTP tab, select `qa-binary.bin` and Upload with F9. Verify the file appears under `loopback-baseline/ftp-root/ftp-start` and the remote pane refreshes. Use the local directory dialog to switch to `desktop-transfer-baseline/download`. Select the remote file and Download with F7, then verify the local listing and size. Use `Get-FileHash -Algorithm SHA256 -LiteralPath <file>` on the source, server copy, and download. All three must match `58932fb6a02052150eb5b2f31c55a779c12ed1650760243ab98a20053366f5fb`. Repeat a binary transfer on the FTPS tab with a distinct local destination or output name. Verify server completion and equality.
4. **ZIP round trip.** On the FTP tab, return to the synthetic upload directory and select `archive-source`. Open **Zip and Upload**, cancel once, and confirm no archive appears. Repeat as `qa-roundtrip.zip` and keep the local ZIP. Verify the local archive and server copy. Select it in the remote pane, invoke **Download and Unzip**, set scratch download and extraction paths, and confirm. Compare extracted `archive-source/zip-payload.bin` byte-for-byte and confirm `archive-source/empty` exists.
5. **Abort at the batch boundary.** Connect a separate tab using **04 Abort**. Select `01-first.bin` and `02-second.bin` in name order and start Upload. After the service log shows first-file progress, press F12 or invoke **Abort**. Verify the session log's abort result, any in-flight partial file length and the absence of a `STOR` or file for `02-second.bin`. Inspect the still-connected original tab separately.
6. **Preferences and favorites.** Change a nondefault preference and cancel, then verify the value did not change. Save another visible preference, save a synthetic connected site with a distinct name, and exit cleanly. Inspect the two serialized files in the synthetic home, relaunch, and verify the saved preference and favorite. For the Java 25 gate, also copy each baseline home from `persistence-baseline/sealed` and `persistence-baseline/legacy` to distinct scratch directories and run `VerifyPersistence.java` with the candidate JAR and appropriate `verify-sealed` or `verify-legacy` argument. Compare its `schema` output against `serialized-schema.txt`.
